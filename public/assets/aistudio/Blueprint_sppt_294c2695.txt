· Loading (skeleton)

Fitur:

2.4 Presensi (AttendanceModule)

Fungsi: siswa isi kehadiran; guru/sekretaris buat & tutup sesi.

Data model (2 koleksi):

ts
// attendanceSessions
{
  id, classId, stage, date, title,
  activityType: 'Rapat'|'Latihan'|'Gladi'|'Pementasan'|'Lainnya',
  targetScope: 'SEMUA'|'PEMAIN_MUSIK'|'PENGURUS_INTI'|'DIVISI'|'PERAN'|'CUSTOM',
  targetDivision?, targetRole?, targetRoles?, targetDivisions?, targetUserIds?,
  isOpen: boolean,
  createdBy, creatorName, creatorRole,
  createdAt, closedAt?, autoMarkedCount?, expectedCount?
}

// attendanceRecords
{
  id, sessionId, studentId, studentName, classId,
  status: 'Hadir'|'Izin'|'Sakit'|'Alpa',
  timestamp,
  isOnBehalf?: boolean, filledBy?, filledByName?, filledByRole?,
  autoMarked?: boolean, autoMarkedAt?
}


Fitur siswa:

· List sesi yang relevan (filter by targetScope vs role/divisi)
· Kalau belum isi & session open → tombol 4 status (Hadir/Izin/Sakit/Alpa)
· Kalau sudah isi → tampil status + timestamp
· Kalau session closed & belum isi → peringatan "Anda Alpa"

Fitur guru/sekretaris:

· Buat sesi (target scope bisa SEMUA, per divisi, per role, custom)
· Tutup sesi → auto-mark Alpa untuk siswa yang belum isi
· Isi on-behalf (untuk siswa yang lupa isi, sebelum tutup)

Alur auto-Alpa:

Sekretaris buat sesi "Latihan Babak 1" target SEMUA, isOpen=true
  → siswa A isi Hadir ✅
  → siswa B isi Izin ✅
  → siswa C tidak isi
Sekretaris klik "Tutup Sesi"
  → closeAttendanceSession()
  → getExpectedStudentsForSession() = semua siswa
  → untuk siswa C: buat record {status: 'Alpa', autoMarked: true}
  → session.isOpen = false


Impact ke nilai: masuk komponen kehadiran (auto-score 4.4).

Fungsi: guru/pengurus buat tugas, siswa submit bukti (foto wajib di tahap PELAKSANAAN).

{

  status: 'BELUM'|'SELESAI'|'TERLAMBAT',

Fitur guru:

· Buat dari template (core/deadlineTemplates.ts berisi ~80 template per stage)
· Buat manual (custom tugas)
· Lihat progress: siapa sudah/belum submit
· Feedback: nilai + komentar per submission
· Carry-over: pindahkan deadline belum selesai ke tahap berikut (via StageManager)

Fitur siswa:

· List tugas yang relevan (filter by targetScope)
· Badge deadline: "HARI INI", "BESOK", "3 hari lagi", "Terlambat X hari"
· Tombol "Tandai Selesai" → upload foto bukti (kalau stage PELAKSANAAN) → submit
· Tampil feedback guru setelah dinilai

Photo evidence (pakai PhotoEvidenceUploader):

· Max 3 foto, kompres ≤300KB/foto
· Auto-filter kata kasar di caption & nama file
· Checkbox deklarasi keaslian foto

Alur submit:

Siswa buka tugas → klik "Tandai Selesai"
  → form muncul: upload foto (wajib) + caption
  → submit → deadlineSubmissions {status: 'SELESAI', submittedAt}
  → recordAuditLog
  → notif ke guru: "X mengumpulkan tugas Y"
Guru review:
  → klik "Beri Feedback"
  → isi feedback → update submission
  → notif ke siswa: "Feedback tugas Y"


Impact ke nilai: masuk tanggung_jawab (auto-score 4.3).

2.8 Rapor Saya (MyGradeModule)

Fungsi: siswa lihat nilai 360° lengkap dengan 2 gate.

Gate 1 — Peer Assessment:

Cek: apakah user sudah nilai semua yang seharusnya?
  → hitung target dari ASSESSMENT_MATRIX[user.role]
  → filter teman sekelas yang match
  → filled = jumlah yang sudah dinilai
  → isComplete = filled >= total
Kalau !isComplete:
  → BLOKIR halaman rapor
  → tampil progress "X/Y", list target belum dinilai
  → tombol "Isi Penilaian Rekan" → navigate 'nilai'


Gate 2 — Waktu Penilaian:

Cek: assessmentStatus = isAssessmentOpen(stageConfig.stageDeadlines, currentStage)
  → kalau not-started: tampil countdown + tanggal buka
  → kalau ended: tampil "sudah ditutup"
  → kalau disabled: tampil "dinonaktifkan guru"
Kalau guru/admin: bypass kedua gate


Konten rapor (setelah gate terbuka):

· Header: nama, role, divisi, kelas + tombol WA tanya guru, unduh XLSX, print PDF
· Nilai Akhir: angka besar + predikat (A/B/C/D/E) + label warna
· Radar Chart: nilai per 4 tahap (PERSIAPAN/PELAKSANAAN/PERTUNJUKAN/PASCA)
· Bar Chart: perbandingan nilai antar tahap
· Siapa yang menilai: 4 kartu (Guru, Koordinator, Rekan, Anggota) jumlah penilaian per kategori
· Rincian per Kriteria: grid kriteria (label, bobot, avg, konversi 0-100, sumber manual/auto)
· Komentar: list komentar penilai (anonim untuk REKAN & BAWAHAN), timestamp, nilai

Kalkulasi nilai akhir:

Untuk setiap tahap:
  catScores = {GURU: [scores], ATASAN: [...], REKAN: [...], BAWAHAN: [...]}
  weights = getAssessorWeights(user.role)
  stageScore = weighted_average(catScores, weights)
  
Final = Σ(stageScore × stageWeight) / Σ(stageWeight)
  (hanya tahap yang ada nilainya)


Anonymization:

· Penilai GURU & ATASAN: tampil nama
· Penilai REKAN & BAWAHAN: tampil "Anonim"

Export XLSX (4 sheet):

1. Ringkasan per tahap
2. Nilai akhir + predikat
3. Rincian kriteria (avg, konversi, sumber)
4. Komentar (tanggal, tahap, kategori, nilai, isi)

· Kirim WA ke siswa belum isi peer
· Edit nilai spesifik (dengan audit log)
· Hapus 1 penilaian

Kriteria penilaian:

Pemeran (6 kriteria):

Kriteria Bobot Sumber
Hafalan Dialog 20% Manual
Penjiwaan Karakter 25% Manual
Proyeksi Suara 15% Manual
Blocking & Movement 15% Manual
Interaksi Panggung 15% Manual

Kriteria Bobot Sumber

1 (Kurang)      → 40

· Kalau Pemeran & kedisiplinan ≤ 2 → total max 75

2.10 Auto-Score Service

Fungsi: hitung skor otomatis dari data tugas & presensi.

computeTaskResponsibility(student, tasks, submissions, stage):

filter tugas relevan:
  - stage match
  - status bukan CANCELLED
  - targetScope match (SEMUA/PERAN/DIVISI/CUSTOM)

untuk setiap tugas:
  cari submission
  kalau belum submit → count BELUM
  kalau SELESAI:
    diff = submittedAt - dueDate (hari)
    -1 (awal) → AWAL
    0 → TEPAT
    1-2 → TELAT_RINGAN
    >2 → TELAT_BERAT
  kalau TERLAMBAT → TELAT_BERAT

pctOnTime = (awal + tepat) / total

Score:
  4: pct >= 90 & tidak ada critical late/missed
  3: pct >= 75 & tidak ada critical late
  2: pct >= 50 & tidak ada critical missed
  1: selain itu

Jika total = 0 → score 3 (netral)
Jika critical missed > 0 → score 1


computeAttendanceScore(student, sessions, records, stage):

filter sesi stage match

untuk setiap record:
  Hadir → hadir++
  Izin/Sakit → izinSakit++
  Alpa → alpa++
    jika activityType Gladi/Pementasan → fatalAlpa = true

pct = (hadir + izinSakit) / total

Score:
  4: pct >= 95
  3: pct >= 85
  2: pct >= 70
  1: pct < 70

Jika total = 0 → score 3 (netral)
Jika alpa >= 3 atau fatalAlpa → score max 2


computePemeranDiscipline(taskScore, attendScore):

avg = (taskScore + attendScore) / 2
return floor(avg)

2.11 Moderasi (ModerationModule)

Fungsi: guru review & validasi penilaian anomali.

Data source: assessments + assessmentHistory

Tabs:

1. Anomali: list penilaian yang terdeteksi anomali
2. Semua: list semua penilaian
3. Riwayat: log revisi (dari assessmentHistory)

Deteksi anomali (detectAnomalies):

· Nilai ekstrem tinggi (semua 4)
· Nilai ekstrem rendah (semua 1)
· Pola mencurigakan (semua nilai sama, bukan 1/4)
· Komentar hilang (nilai ≤2 tanpa komentar)
· Ketidaksesuaian data (manual tinggi vs auto rendah)
· Gap manual vs auto (selisih ≥ 2)
· Skor rendah tanpa alasan (semua 1, komentar < 20 char)

Aksi:

· Validasi: log "sudah divalidasi" (audit log)
· WA Klarifikasi: kirim WA ke penilai
· Hapus: hapus penilaian (log ke history)

Severity badge:

· HIGH (merah): tindakan segera
· MEDIUM (kuning): perlu konfirmasi
· LOW (biru): pantau

🔧 3. CROSS-CUTTING FEATURES

3.1 Notifikasi Multi-Channel

In-app notification (Firestore notifications):

· Tampil di Navbar (badge unread)
· Tampil di NotificationPage
· Real-time via onSnapshot

WhatsApp deep link:

· Format URL: https://wa.me/{62xxx}?text={encoded_message}
· Dipakai di:
· Booking (notif siswa/guru)
· Assessment (WA ke siswa belum isi peer)
· Aduan (guru reply ke siswa)
· Reminder (kalau mau)
· Tidak auto-send (browser buka WA tab)
· Alasan: Firebase client tidak bisa send WA langsung (butuh backend)

3.2 Reminder Otomatis (utils/reminder.ts)

Scheduler (client-side):

· Interval 30 menit di App.tsx (via useEffect)
· Panggil runAllReminders(classId)

5 jenis reminder:

1. Deadline: H-3, H-1, H-1 jam, overdue
2. Jadwal: H-1, H-1 jam
3. Kas: H-3, H-1, overdue
4. Booking pending: > 12 jam
5. Booking overdue: lewat endTime + 10 min

Anti-duplikat: pakai reminderLog (cek itemId + reminderKey).

3.3 Audit Log

Setiap aksi penting di-log:

· Login, logout
· CRUD (create, update, delete)
· Assessment (nilai)
· Submit (task, kas, dll)

Data: user, action, target, detail, timestamp.

Akses: guru/admin bisa lihat semua; siswa hanya lihat milik sendiri.

3.4 Export System

XLSX (utils/exportXLSX.ts):

· Pure JS, tanpa library
· Multi-sheet support
· Style header (bold + dark bg)
· Auto column width
· Numeric detection (kecuali string yang diawali 0)

DOCX (utils/exportDOCX.ts):

· Pure JS OOXML + ZIP
· Kop surat (header)
· Table, signature block
· Compatible: Word, LibreOffice, WPS

CSV (bonus):

· Fallback paling aman
· BOM UTF-8 untuk Excel

3.5 Backup & Restore

Export: 24 collection → JSON → download
Import: validate → restore (merge) → batch write

Collections yang di-backup:
classes, users, productions, tasks, assessments, assessmentHistory, attendanceSessions, attendanceRecords, schedules, scheduleConfirmations, documents, broadcasts, complaints, notifications, promptBooks, deadlines, deadlineSubmissions, kasSettings, kasPayments, properties, musicCues, faceCharts, costumes, auditLogs, reminderLog, driveSubmissions

📊 4. ALUR KERJA UTAMA

4.1 Alur Produksi Teater (4 Tahap)

PERSIAPAN (bobot 20%)
  ├─ Master Timeline & perizinan (Pimpro)
  ├─ RAB Final (Bendahara)
  ├─ Konsep penyutradaraan (Sutradara)
  ├─ Audisi & casting (Sutradara)
  ├─ Sketsa panggung (Koor Panggung)
  ├─ Face chart & costume chart (Koor Rias, Busana)
  └─ Cue sheet awal (Koor Musik)

PELAKSANAAN (bobot 35%)
  ├─ Latihan rutin (Sutradara, Asisten)
  ├─ Pembuatan properti (Koor Perlengkapan)
  ├─ Konstruksi set (Koor Panggung)
  ├─ Proses kostum: potong → jahit → fitting (Koor Busana)
  ├─ Uji rias (Koor Rias)
  ├─ Poster & teaser (Koor Publikasi)
  └─ Cue sheet final (Koor Musik)

PERTUNJUKAN (bobot 30%)
  ├─ Run-Through penuh
  ├─ Technical Rehearsal
  ├─ Gladi Resik
  └─ Pementasan Hari-H

PASCA (bobot 15%)
  ├─ LPJ Produksi (Pimpro)
  ├─ LPJ Keuangan (Bendahara)
  ├─ Inventaris & pengembalian properti/kostum
  ├─ Arsip dokumentasi
  └─ Evaluasi & refleksi


4.2 Alur Penilaian 360°

1. Siswa isi peer assessment (gate)
   ↓
2. Guru buka jadwal penilaian (AssessmentSchedule)
   ↓
3. Semua assessor isi form:
   - Guru → semua siswa
   - Atasan → bawahan
   - Rekan → peer
   - Bawahan → atasan
   ↓
4. Sistem hitung skor otomatis (auto-score)
   ↓
5. Guru moderasi anomali (ModerationModule)
   ↓
6. Guru tutup penilaian (end date)
   ↓
7. Siswa lihat rapor (MyGradeModule)
   ↓
8. Guru export rekap (GradeRecapModule)


4.3 Alur Kas

1. Bendahara buat periode kas (KasModule)
   - Judul, nominal, deadline
   ↓
2. Siswa bayar → Bendahara centang
   ↓
3. Sistem kirim reminder otomatis (H-3, H-1, overdue)
   - ke siswa belum bayar
   - ke bendahara (laporan)
   ↓
4. Bendahara rekap → export XLSX


4.4 Alur Booking Alat

1. Siswa book (minimal H-2)
   - alat, tanggal, jam, tujuan
   ↓
2. Notif ke guru (WA + in-app)
   ↓
3. Guru approve/reject
   ↓
4. Kalau approve:
   - Siswa ambil alat → foto OUT
   - Status CHECKED_OUT
   ↓
5. Siswa pakai → kembalikan → foto IN
   - Status RETURNED
   ↓
6. Kalau lewat batas → status OVERDUE
   - Reminder otomatis ke guru & siswa

🚀 7. PERFORMANCE & RELIABILITY

Performance

· onSnapshot untuk real-time data (hindari refetch manual)
· useMemo untuk heavy computation (filter, group, sort)
· useCallback untuk handler (hindari re-render)
· Photo compression sebelum upload (max 300KB)
· Pagination: limit query (200/500), "load more" kalau perlu
· Batch write untuk bulk operations

Reliability

· ErrorBoundary di App level (catch runtime errors)
· Global error handler di main.tsx (window.onerror, unhandledrejection)
· Fallback UI (LoadingScreen, ModulePlaceholder)
· Try/catch di semua async call — minimal log
· Guard: null checks di critical path (divisionName, className)
· Offline: Firebase SDK auto-retry

Security

· Firestore Rules (harus di-set di console):
· users: read all authenticated, write own
· assessments: read all authenticated, write assessor only
· auditLogs: write authenticated, read guru/admin only
· userCredentials: read guru/admin only
· Role normalization: Guru Pembina → Guru Pengampu di enrichUser
· Protected photo: block screenshot, disable download
· Forbidden words filter: caption, reply
